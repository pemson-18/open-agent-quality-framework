# Project Governance (Proposed)

OAQF is currently an early-stage proposal. This document describes an initial governance approach for community discussion; it does not imply an existing governing body.

## Principles

- Open discussion and transparent decisions.
- Technical merit and evidence over institutional status.
- Clear separation between specification authorship and evaluation claims.
- Disclosure of relevant conflicts of interest.
- No single vendor should control the standard.
- Backward compatibility should be considered for published versions.

## Change process

1. Open an issue describing the problem.
2. Submit an RFC for substantial changes.
3. Discuss scope, alternatives, risks, and compatibility.
4. Record the decision and rationale.
5. Update specifications, schemas, and tests together.
6. Publish a versioned release.

## Independence

Conformance evaluation should disclose who performed it, which agent configuration was tested, which tests were run, and any limitations. Independent evaluation should be encouraged.
