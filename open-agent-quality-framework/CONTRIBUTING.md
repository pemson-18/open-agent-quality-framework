# Contributing

Thank you for considering a contribution to OAQF.

## Before contributing

- Read `README.md` and `SKILL.md`.
- Search existing issues and discussions to avoid duplicate work.
- For substantial changes, open an issue or proposal first.

## What makes a good contribution?

- Clear definitions that avoid ambiguity.
- Requirements that can be observed or tested.
- Test cases with explicit expected outcomes.
- Evidence, rationale, and relevant references.
- Compatibility with model- and framework-independent use.
- Clear statements of limitations and unresolved questions.

## Normative language

Use these terms consistently:

- **MUST / MUST NOT:** mandatory requirement.
- **SHOULD / SHOULD NOT:** recommended practice; deviations need a reason.
- **MAY:** optional capability or practice.

Do not use normative terms casually. Explain how a requirement can be evaluated.

## Pull requests

Include:
1. The problem being addressed.
2. The proposed change.
3. Rationale and relevant prior work.
4. Compatibility or migration implications.
5. Tests or evidence supporting the change.
6. Known limitations.

## Conduct

Be respectful, evidence-oriented, and open to correction. Critique ideas and implementations, not people.
